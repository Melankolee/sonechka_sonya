# travel

Личное PWA для поездок: рейсы, проживание, трансфер, заметки, чеклист и
документы. Поездки создаются и редактируются прямо в приложении, PDF и фото
загружаются туда же. После загрузки всё работает на iPhone без интернета,
документы тоже открываются офлайн.

Адрес: **https://travel.sonechka-sonya.ru** (логин `travel`, пароль — у владельца).

С остальным репозиторием (сайт приглашения в `site/`, `deploy/`) не связано:
свой `package.json`, свой сервис, свой workflow, свои каталоги на сервере и
свой блок в Caddy.

```
travel/
├── src/
│   ├── App.tsx              экраны и навигация на хэше (#/section/…, #/doc/…, #/trips, #/new, #/edit/…)
│   ├── sw.ts                Service Worker: precache оболочки, обновления
│   ├── pages/               главный экран, разделы, документ, список поездок, редактирование
│   ├── components/          блок офлайна, PDF-viewer (pdf.js), редакторы разделов и документов
│   ├── hooks/               состояние поездки, обновление приложения, маршрут, чеклист
│   ├── services/            сеть и API, загрузка для офлайна, проверка готовности, форматирование
│   ├── storage/db.ts        IndexedDB
│   └── types/trip.ts        формат trip.json
├── server/travel-api.py     API: поездки и документы (только стандартная библиотека Python)
├── public/                  иконки, robots.txt (pdfjs/ генерируется при сборке)
├── deploy/                  Caddy, установка API, пароль
└── vite.config.ts
```

## Как пользоваться

- **Поездки** (вверху слева) — список, «Новая», переход к редактированию.
- **Изменить** (вверху справа) — правка активной поездки: основное, документы,
  перелёты, проживание, трансфер, заметки, чеклист. Текст уходит кнопкой
  **Сохранить**, файлы — сразу при загрузке.
- В редактировании внизу: **Сделать активной** (она на главном экране) и
  **Удалить поездку**.
- После любой правки копия на телефоне обновляется сама. Правки с другого
  устройства телефон видит при открытии: **Доступно обновление поездки → Обновить**.
- Редактировать можно только с интернетом; смотреть — всегда.

## Как устроено

**Сервер.** `server/travel-api.py` пишет поездки обычными файлами в
`/var/lib/travel/trips/` (`index.json` — какая активна, `<id>/trip.json`,
`<id>/documents/`). Читает их не сервис, а Caddy напрямую по `/trips/*`.
Любая правка увеличивает `version` поездки. Сохранение формы передаёт версию,
с которой начиналась правка: если поездку успели поменять в другом месте,
сервер отвечает 409 и ничего не затирает. Тип загруженного файла сервер
определяет по содержимому (PDF, JPEG, PNG, WebP, HEIC), до 50 МБ. Документ
после загрузки не меняется: новый файл — новый id.

**Телефон.** Три слоя, ни один не полагается на HTTP-кеш Safari.

1. **Оболочка** — Service Worker (`src/sw.ts`) кладёт в precache HTML, JS, CSS,
   manifest, иконки и всё, что нужно pdf.js. Запуск с экрана «Домой» в
   авиарежиме берёт `index.html` оттуда.
2. **Поездка и документы** — IndexedDB (`src/storage/db.ts`). Синхронизация
   (`src/services/sync.ts`) берёт свежий `trip.json`, документы, которых на
   телефоне ещё нет, скачивает, уже скачанные копирует локально, каждый файл
   читает обратно и сверяет размер. Новая версия становится текущей только
   после того, как легли все файлы — оборванная загрузка не портит прежнюю копию.
3. **Проверка готовности** (`src/services/verify.ts`) — при запуске и после
   синхронизации смотрит на то, что реально лежит в хранилищах:
   «Готово к офлайну — доступно 5 из 5 документов» или
   «Офлайн-копия неполная — не хватает: Страховка».

PDF рисуются внутри приложения pdf.js-ом из байтов в IndexedDB. Кнопка
**Сохранить в «Файлы»** отдаёт файл в системный Share Sheet — запасной вариант.

## Разработка

```sh
cd travel
npm install
TRAVEL_DATA=./data npm run api     # API на 127.0.0.1:8788, данные в travel/data/
npm run dev                        # http://localhost:5173, /api и /trips проксируются в API
```

В `npm run dev` Service Worker выключен; офлайн проверяется на сборке:

```sh
npm run build        # проверка типов + dist/
npm run preview      # http://localhost:4173, с SW и той же CSP, что на проде
```

Нужны Node 22.13+ (требование pdf.js) и Python 3.9+.

## Деплой

Push в `main`, задевающий `travel/` (кроме `deploy/` и README), запускает
[.github/workflows/deploy-travel.yml](../.github/workflows/deploy-travel.yml):
сборка, rsync `dist/` в `/var/www/travel.sonechka-sonya.ru` в два прохода
(сначала новые бандлы, потом `index.html`/`sw.js`), затем обновление API, если
менялся `server/travel-api.py`. Обновлятор проверяет синтаксис, перезапускает
сервис и откатывает, если `/api/health` не ответил. Вручную: Actions →
Deploy travel → Run workflow.

После деплоя новой сборки телефон при следующем открытии покажет
**Вышла новая версия приложения → Перезагрузить**.

### Разовая настройка сервера (от root)

На сервере (185.103.101.75) Docker нет, все сайты отдаёт общий Caddy.

```sh
rsync -rlptz travel/deploy travel/server root@185.103.101.75:/tmp/travel/
ssh root@185.103.101.75 'cd /tmp/travel/deploy && bash server-setup.sh && bash api-setup.sh'
ssh -t root@185.103.101.75 'bash /tmp/travel/deploy/travel-auth.sh travel'   # спросит пароль
ssh root@185.103.101.75 'bash /tmp/travel/deploy/caddy-travel.sh'
```

- [server-setup.sh](deploy/server-setup.sh) — каталог сборки, владелец `deploy`.
- [api-setup.sh](deploy/api-setup.sh) — пользователь `travel-api`, юнит
  `travel-api` на 127.0.0.1:8788, данные в `/var/lib/travel`, обновлятор для
  CI (`deploy` может выполнить через sudo только его).
- [travel-auth.sh](deploy/travel-auth.sh) — пароль, см. ниже.
- [caddy-travel.sh](deploy/caddy-travel.sh) — вставляет
  [caddy-travel.caddy](deploy/caddy-travel.caddy) в общий Caddyfile между
  своими маркерами: бэкап, `caddy validate`, откат при ошибке, проверка
  соседних сайтов. Блок `birthday.sonechka-sonya.ru` не трогается. С
  `TRAVEL_AUTH=логин:пароль` печатает ещё и коды/типы ответов с паролем.

DNS: A-запись `travel` → 185.103.101.75 в зоне Aeza.

## Пароль

Весь сайт, включая API и документы, закрыт HTTP basic auth в Caddy (логин
`travel`). Хеш лежит только на сервере, в `/etc/caddy/travel-auth.caddy`; блок
сайта подключает его через `import`. В git хеша нет: репозиторий публичный, а
bcrypt короткого пароля перебирается офлайн. Сменить пароль:

```sh
rsync -rlptz travel/deploy root@185.103.101.75:/tmp/travel/
ssh -t root@185.103.101.75 'bash /tmp/travel/deploy/travel-auth.sh travel'
```

Скрипт сам проверит конфиг и перезагрузит Caddy. Офлайн пароль не нужен —
оболочка берётся из Service Worker, данные из IndexedDB. Онлайн установленное
приложение на iOS может спрашивать пароль заново после перезапуска.

## Резервная копия

Все поездки — это `/var/lib/travel/trips/` на сервере:

```sh
rsync -rlptz root@185.103.101.75:/var/lib/travel/trips/ ./travel-backup/
```

## Проверка офлайна на iPhone

Важно: **у Safari и у приложения на экране «Домой» разные хранилища.**
Скачанное во вкладке Safari в установленном приложении не появится. Вне
установленного приложения на iPhone об этом напоминает подсказка вверху.

1. Safari → https://travel.sonechka-sonya.ru → логин и пароль → «Поделиться» →
   **На экран «Домой»**.
2. Открыть приложение **с иконки** (с интернетом; пароль может спросить ещё
   раз). Подождать пару секунд: Service Worker докачивает оболочку (~5 МБ).
3. Создать поездку или открыть существующую; дождаться
   «✓ Готово к работе без интернета» и «Готово к офлайну — доступно N из N
   документов». Если вместо этого «Приложение ещё не закешировано» — закрыть и
   открыть приложение ещё раз с интернетом.
4. Полностью закрыть приложение (свайп вверх в переключателе).
5. Включить **авиарежим** (и выключить Wi-Fi, если он включается вместе с ним).
6. Открыть приложение с иконки.
7. Ожидается: поездка на экране сразу, метка «Офлайн», «Готово к офлайну».
   Никаких сетевых ошибок, «Поездки» и «Изменить» неактивны.
8. Открыть каждый раздел (отметки чеклиста ставятся и без сети).
9. Открыть каждый документ: страницы рисуются, зум `− / +` работает,
   «Сохранить в „Файлы“» открывает Share Sheet.

Тот же сценарий прогнан автоматически в Chromium и WebKit (Playwright):
создание поездки в интерфейсе, загрузка 5 PDF, заполнение разделов,
сохранение → остановка API и веб-сервера → открытие заново тем же профилем:
все разделы и PDF на месте. Правка с «другого устройства» даёт «Доступно
обновление поездки», при обновлении ни один PDF не скачивается повторно;
новый `sw.js` даёт «Вышла новая версия приложения». Настоящий iPhone это не
заменяет — пройти пункты выше руками.
