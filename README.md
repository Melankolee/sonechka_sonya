# sonechka_sonya

Приглашение на день рождения — статический сайт в [site/](site/).

Страница одна для всех: персональные ссылки по именам (`/nastia`, `/uliya`,
`/ksusha`) и отдельная страница Кости (`/kostya`) удалены 3 октября 2026, вместе
с обращением по имени, подписью на конверте и фильтром напитков. Найти их можно
в истории git до этой даты.

## Деплой

Автоматический: пуш в `main`, задевающий `site/**`, запускает
[.github/workflows/deploy.yml](.github/workflows/deploy.yml), который заливает
`site/` по rsync в `/var/www/sonechka-sonya.ru` на 185.103.101.75.
Можно запустить и вручную — вкладка Actions → Deploy site → Run workflow.

Секреты репозитория:

| Секрет | Значение |
| --- | --- |
| `DEPLOY_HOST` | `185.103.101.75` |
| `DEPLOY_USER` | `deploy` |
| `DEPLOY_SSH_KEY` | приватный ключ пары, чей публичный лежит в [deploy/server-setup.sh](deploy/server-setup.sh) |
| `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -t ed25519 185.103.101.75` |

Разовая настройка сервера — [deploy/server-setup.sh](deploy/server-setup.sh)
(заводит непривилегированного пользователя `deploy` с доступом только к каталогу
сайта; root у CI намеренно нет, сервер общий с другими сервисами).

### Сервер

С 3 октября 2026 сайт живёт на 185.103.101.75 (Aeza, Ubuntu 26.04). Сервер
общий: рядом job-radar.su и сервисы aso-kw.ru, все за одним Caddy. Прежний
45.146.131.218 к моменту переезда был недоступен (сменились ключи хоста, порты
80/443 закрыты), ответы гостей оттуда не перенесены.

Отдаёт сайт Caddy — блок [deploy/caddy-sonechka-sonya.caddy](deploy/caddy-sonechka-sonya.caddy)
в общем `/etc/caddy/Caddyfile`, между маркерами `# >>> sonechka-sonya.ru`.
Вставляет его [deploy/caddy-site.sh](deploy/caddy-site.sh): бэкап Caddyfile,
`caddy validate`, откат при ошибке, проверка соседа до и после. Сертификат
Caddy выпускает и продлевает сам.

Адрес сайта — **birthday.sonechka-sonya.ru**. Голый `sonechka-sonya.ru` и `www`
отвечают редиректом 307 туда же с сохранением пути. Редирект временный, чтобы
голый домен можно было потом отдать под другое. Неотправленные ответы в
`localStorage` привязаны к домену и со старого адреса не переезжают.

Лимита запросов на `/api/`, как был `limit_req` в nginx, нет: в сборке Caddy нет
модуля `rate_limit`. Файл ответов от разрастания держат лимиты самого сервиса —
тело до 8 КБ, не больше 5000 записей.

DNS — зона в панели Aeza (`a/b.aeza-dns.net`), записи `@`, `www` и `birthday` → 185.103.101.75.

## Ответы гостей

Гостья нажимает «Я приду» → `POST /api/answers` → сервис `sonechka-answers`
(127.0.0.1:8787, [deploy/answers-api.py](deploy/answers-api.py)) дописывает строку
в `/var/lib/sonechka/answers.jsonl`. Читает их страница
[birthday.sonechka-sonya.ru/sonechka](site/sonechka.html): последний ответ каждого
гостя плюс общий подсчёт. Гости различаются по полю `name`; поля для имени на
странице сейчас нет, поэтому все ответы сливаются в одну карточку «Гость без
имени». Сервис по-прежнему принимает `guest` и `place` от старых страниц. Если сети нет, ответ ждёт в `localStorage` и досылается при
следующем открытии — гостья ошибки не видит.

Блокнот «А есть идея?» (над блоком с вишлистом) шлёт мысли туда же, но своей
записью с полем `idea`: листов можно оторвать сколько угодно, до и после «Я
приду». Отрыв — копия листа с рваным краем улетает за верх экрана, сам блок
страницы остаётся на месте (`tearOff` в [site/index.html](site/index.html)).
Записи с непустым `idea` страница `/sonechka` показывает отдельным списком в
карточке гостьи и не считает за ответ. Не доехавшие мысли ждут очередью в
`localStorage` (`sonechka:notes`) и досылаются при следующем открытии.

Кнопка «Очистить» на той же странице шлёт `DELETE /api/answers`. Насовсем ничего
не пропадает: ответы уезжают в `/var/lib/sonechka/archive/answers-<дата>.jsonl`,
а живой файл остаётся пустым. Вернуть — скопировать строки из архива обратно.
Так решено потому, что страница открыта без пароля и кнопка стоит рядом с
«Обновить»: нажатие сгоряча не должно быть необратимым.

Установка на чистый сервер целиком (от root), так переезжали 3 октября 2026:

```
rsync -rlptz deploy/ root@185.103.101.75:/tmp/sonechka-deploy/
ssh root@185.103.101.75 'cd /tmp/sonechka-deploy && bash server-setup.sh && bash answers-setup.sh && bash ci-api-access.sh'
rsync -rlptz --delete site/ root@185.103.101.75:/var/www/sonechka-sonya.ru/
ssh root@185.103.101.75 'chown -R deploy:deploy /var/www/sonechka-sonya.ru && bash /tmp/sonechka-deploy/caddy-site.sh'
```

[answers-setup.sh](deploy/answers-setup.sh) ставит сервис и systemd-юнит,
[caddy-site.sh](deploy/caddy-site.sh) подключает сайт и `/api/` к Caddy.
Caddyfile правится только этим скриптом и только руками — автодеплой его не касается.

### Дальнейшие правки API — обычным `git push`

[ci-api-access.sh](deploy/ci-api-access.sh) запускается один раз и снимает
необходимость ходить на сервер руками: после него правки
[answers-api.py](deploy/answers-api.py) уезжают тем же деплоем, что и сайт.

Root пользователю `deploy` при этом не достаётся. Он кладёт файл в свой
`~/api-staging/` и выполняет единственную разрешённую ему команду —
`sudo /usr/local/sbin/sonechka-update-api`. Обновлятор принадлежит root, для
`deploy` не перезаписываем, проверяет файл `py_compile`, сверяет с текущим
(не изменился — сервис не перезапускается), а если после рестарта
`/api/health` молчит пять секунд — возвращает предыдущую версию. Вечер важнее
свежей правки.

Ручка `GET /api/answers` и страница `/sonechka` открыты без пароля: кто угадает
адрес — прочитает ответы.
